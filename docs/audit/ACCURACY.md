# Technical accuracy audit

Reviewed all 15 incidents in `pack-k8s.js`, `pack-db.js`, `pack-net.js`, `pack-cid.js`, and `pack-obs.js`.

| Incident | Offending line / issue | Severity | Corrected version |
|---|---|---:|---|
| k8s-imagefs-diskpressure | `kubectl cordon -l kubernetes.io/os=linux` | HIGH | `kubectl get nodes -l kubernetes.io/os=linux -o name \\| xargs -r kubectl cordon` (or name one node explicitly). `kubectl cordon` does not accept a label selector. |
| k8s-imagefs-diskpressure | `aws autoscaling terminate-instance-in-auto-scaling-group ...` | MED | Use a complete, explicit command, e.g. `aws autoscaling terminate-instance-in-auto-scaling-group --instance-id i-... --should-decrement-desired-capacity false`; `...` is not copy-pasteable. |
| k8s-pdb-security-drain | `kubectl drain ... --force --ignore-daemonsets` output says `--force` cannot override the PDB | LOW | State precisely: drain still respects the PDB; `--force` permits unmanaged pods, while a separate local-storage condition can still block eviction. |
| k8s-autoscaler-pending-capacity | `eksctl get nodegroup --cluster prod: report-on-demand...` | LOW | `eksctl get nodegroup --cluster prod` is the command; render the returned row as output, not as part of the shell command. |
| db-aurora-idle-tx-pool | `412 active connections; pool limit: 400`, followed by `active 86; idle 194; idle in transaction 118` | HIGH | Distinguish total from active: `412 total connections (pool limit 400)` and make the state counts sum to 412 (or change the headline to match the 398 shown). |
| db-aurora-idle-tx-pool | `aws rds modify-db-parameter-group --parameters ParameterName=max_connections,ParameterValue=800` | HIGH | Include the group: `aws rds modify-db-parameter-group --db-parameter-group-name <group> --parameters "ParameterName=max_connections,ParameterValue=800,ApplyMethod=pending-reboot"`; verify the Aurora family and reboot requirement. |
| db-aurora-idle-tx-pool | `pg_terminate_backend...` output: `pg_terminate_backend: 118 rows` | MED | PostgreSQL emits one boolean result per terminated PID. Say `118 rows returned, each value t`, or wrap it in `SELECT count(*) ...` if a count is intended. |
| db-postgres-migration-lock | `ALTER TABLE ... running for 27 minutes` and `pid 28109 holds ShareLock` | MED | Do not infer the blocker from the migration text alone; show the blocker query and relation, e.g. join `pg_locks` on relation and report `28109`'s granted lock. |
| db-dynamodb-hot-partition | `aws dynamodb describe-contributor-insights ...` output gives `Top key ... 96.1%` | HIGH | `describe-contributor-insights` returns configuration/status, not top keys. Use Contributor Insights' `GetInsightRuleReport`/CloudWatch output (or label this as console output) for top-key data. |
| net-dns-servfail-az1 | `aws ec2 replace-route ... --destination-cidr-block 10.0.0.2/32 --vpc-peering-connection-id pcx-91` | MED | Verify that the resolver endpoint is reachable through that peering route; otherwise use the actual route target (for example a transit gateway/NAT path). A VPC resolver address is not automatically a peering target. |
| net-tls-handshake-wrong-secret | `kubectl ... annotate svc ingress-public acm-cert-arn=...` as the generic fix | HIGH | Change the actual serving listener reference: for an AWS Load Balancer Controller Ingress use `alb.ingress.kubernetes.io/certificate-arn=...` on the Ingress; for another controller use its documented TLS Secret/listener configuration. |
| net-tls-handshake-wrong-secret | `READY=True` Secret serial `7F02` is asserted, but no command reads that certificate | MED | Add `kubectl ... get secret ... | base64 -d | openssl x509 -noout -serial` and identify the exact listener/Ingress reference before changing it. |
| net-edge-504-healthcheck-path | `TargetHealth: unused Reason=Target.ResponseCodeMismatch` is shown as the result of `describe-target-health` | LOW | Render the real AWS CLI shape: `TargetHealthDescriptions[].TargetHealth.State=unhealthy, Reason=Target.ResponseCodeMismatch, Description=...`; `TargetHealth` is not a literal top-level output line. |
| cid-checkout-feature-flag-path | `curl -X PATCH flags/promo_v2 ...` | MED | Use the real flag service URL and required headers/auth/body, e.g. `curl -fsS -X PATCH https://flags.example/api/v1/flags/promo_v2 -H 'Content-Type: application/json' -d '{"eu":false}'`; the current command has no host and is not executable. |
| cid-terraform-lock-drift | `aws dynamodb get-item --table-name tf-locks` | HIGH | Supply the backend lock-table key, e.g. `aws dynamodb get-item --table-name tf-locks --key '{"LockID":{"S":"<backend-lock-id>"}}'`; DynamoDB `get-item` requires `--key`. |
| cid-terraform-lock-drift | `terraform force-unlock ... prod/network` | HIGH | Terraform lock IDs are normally the exact numeric/UUID ID printed in the lock error, not a backend path. Use `terraform force-unlock <exact-lock-id>` only after confirming the writer is dead. |
| cid-terraform-lock-drift | `terraform force-unlock prod/network` followed by `Do you really want...` | MED | If intentionally interactive, show `terraform force-unlock <exact-lock-id>` and its prompt; do not present a path as the lock ID. |
| cid-argocd-secret-rotation-drift | `argocd app set billing-prod --ignore-differences Secret` | MED | Use a documented resource selector, such as `--ignore-differences group=,kind=Secret,name=payment-api,namespace=billing` (or configure it in the Application manifest). Ignoring all Secrets is dangerously broad. |
| obs-nat-egress-cost-spike | `--time-period Start=2026-10-17,End=2026-10-19` called “last 24 hours” | HIGH | Cost Explorer end is exclusive; use adjacent 24-hour dates/timestamps appropriate to the API, e.g. `Start=2026-10-18,End=2026-10-19`, and state the timezone. |
| obs-nat-egress-cost-spike | `41,209,884,672` bytes and `$1,184.22` in one hour | HIGH | 41.2 GB at the stated NAT rate of $0.045/GB is about $1.85, not $1,184.22. Either use about 26.3 TB for $1,184 at that rate or change the cost to match 41.2 GB. |
| obs-nat-egress-cost-spike | `--group-by Type=USAGE_TYPE` | MED | Cost Explorer group-by requires a key: `--group-by Type=USAGE_TYPE,Key=UsageType` (or use the correct CLI JSON syntax). |
| obs-nat-egress-cost-spike | `aws ec2 create-vpc-endpoint --service-name ...` | HIGH | A gateway endpoint needs its VPC and route tables: `aws ec2 create-vpc-endpoint --vpc-id vpc-... --vpc-endpoint-type Gateway --service-name com.amazonaws.ca-central-1.s3 --route-table-ids rtb-...`; also ensure the route tables are the workload's. |
| obs-kafka-poison-message-lag | `billing-writer 7 9182441 11982441 2,000,000 billing-3` | HIGH | `kafka-consumer-groups --describe` output includes `GROUP TOPIC PARTITION CURRENT-OFFSET LOG-END-OFFSET LAG CONSUMER-ID HOST CLIENT-ID`; include `billing-events` and the remaining columns, or label the abbreviated display as synthetic. |
| obs-kafka-poison-message-lag | `kafka-delete-records --offset-json` | MED | The Apache distribution command is normally `kafka-delete-records.sh --bootstrap-server ... --offset-json-file billing-events-all.json`; do not imply deletion is a safe recovery operation. |
| obs-metrics-pipeline-silent | `promtool query instant http://prometheus.prod up` | LOW | Valid only with a `promtool` version that supports the query subcommand and network access; otherwise use `curl -g 'http://prometheus.prod/api/v1/query?query=up'`. |
| obs-metrics-pipeline-silent | `curl -X POST https://status.example/api/incidents ...` | MED | Replace the placeholder with the actual status API endpoint and required authentication/schema, or label it explicitly as pseudocode; as written it is not a runnable command. |
