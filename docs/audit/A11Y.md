# ON-CALL WCAG 2.2 AA accessibility audit

Static audit of `index.html`, `assets/app.css`, and `src/app.js`; contrast ratios are computed sRGB relative luminance ratios (rounded to 2 decimals). Target: WCAG 2.2 AA.

## HIGH

- **1.4.3 Contrast (Minimum):** `--text-4: #555c68` is used by `.brand-sub`, `.page-meta`, `.howto h2`, HUD/table labels, footer, captions, and notes. Ratios are **2.88:1 on `--bg #0c0d11`**, **2.68:1 on `--panel #14161c`**, **2.53:1 on `--panel-2 #191c23`**, and **2.34:1 on `--panel-3 #1f232b`** (normal-size text; required 4.5:1). Replace with a lighter token (at least 4.5:1 on each actual background).
- **1.4.3 Contrast (Minimum):** `.stage-head`, `.prompt`, `.hint-btn`, and `.choice .go` use `--text-3: #767d8a`; measured **4.37:1 on panel**, **4.12:1 on panel-2**, and **3.80:1 on panel-3** (required 4.5:1). Lighten the token or use `--text-2`.
- **4.1.2 Name, Role, Value / 4.1.3 Status Messages:** `#log[role=log][aria-live=polite]` receives text one character chunk at a time in `appendLine()` (`src/app.js:132-167`). Each `textContent` mutation can be announced repeatedly, producing an announcement storm and making the game effectively unusable with a screen reader. Disable live announcements during typing and announce each completed line once via a separate, concise status node (or batch updates in a single DOM mutation).

## MED

- **2.4.3 Focus Order / 2.4.7 Focus Visible:** `show()` (`src/app.js:98-107`) only focuses elements marked `[data-autofocus]`; the play screen has none. After activating `#start-btn`, focus remains on a now-hidden control while `#choices` is populated. Move focus to the first choice (or `#log`) when play starts and to `#again-btn`/postmortem heading when ending. Keep the existing `:focus-visible` outline and ensure dynamically created `.choice` buttons retain it.
- **2.1.1 Keyboard:** `document` key handling (`src/app.js:439-455`) treats Enter on the title screen as “start” even when `#seed-input` is focused. Pressing Enter to submit/replay a seed starts a random shift instead of the entered seed. Ignore global shortcuts while an input/textarea/select has focus, or make the seed form explicit and submit it.
- **2.4.6 Headings and Labels:** `#screen-play` has `aria-label` but no visible or programmatic heading; the stage title is a `span`. Add an `h2`/`h3` for the incident screen (or an `sr` heading) and associate the stage content with it. The page has `h1` and title/postmortem headings, but the play section is a semantic gap.
- **1.3.1 Info and Relationships:** `#hud` labels are plain nested `div`s (`.k`/`.v`), not a definition list or labelled groups. Use `dl/dt/dd`, or expose each metric as a labelled region so screen readers get the label/value relationship.
- **1.3.1 Table semantics:** `table.pm` has a caption and `scope="col"` headers, including the `#` column, which is correct. However, the empty `#pm-tbody` before a run has no explicit empty-state text, and the `#` cells are generated as plain `td` values. Add an accessible “No decisions yet” row when empty; consider `th scope="row"` for decision numbers if they identify rows.
- **1.4.11 Non-text Contrast:** `.icon-btn` is only about 32px high (`padding:6px 9px`, 11px line-height), `.hint-btn` about 29px, and `.btn-sm` about 35px; visible borders use `--line-2`/`--line-3` (for example `#2d313b` on `--panel-2` is approximately **1.40:1**, and `#3a3f4b` on panel is approximately **2.05:1**). Increase interactive boundary contrast to 3:1 and make mobile targets at least 44×44 CSS px, or provide equivalent spacing/target area.
- **1.4.1 Use of Color:** HUD `.v.warn/.bad/.good`, `.vd.good/.warn/.bad`, and grade classes convey outcome/status primarily by amber/red/green. Some values have text, but the grade is a color-only visual distinction (`#pm-grade` is `aria-hidden="true"` and only shows A–F). Add a visible text verdict/status or non-color symbol/pattern and expose the grade to assistive technology.
- **2.3.3 Animation from Interactions / 2.2.2:** reduced-motion CSS disables animations/transitions and JS makes typing instant, but the default typewriter is a timed sequence and `scroll-behavior:smooth` is used. Provide a user-visible “instant text” option or ensure all generated announcements and interaction outcomes do not depend on waiting; preserve the existing `prefers-reduced-motion` handling.

## LOW

- **2.4.1 Bypass Blocks:** skip link exists and targets `#main`, but it is visually positioned off-screen until `:focus` rather than `:focus-visible`; use `:focus-visible` consistently and verify it remains visible at 200% zoom.
- **2.4.4 Link Purpose:** footer links (“Built by … · source”) are understandable in context, but give the GitHub link an explicit accessible name such as “Source code” for isolated screen-reader link lists.
- **2.5.3 Label in Name:** the visible “SOUND OFF” and “EXIT” button names are adequate; keep icon/visible labels synchronized when state changes (currently done for sound).

## Passing/positive checks

- `html[lang="en"]`, a descriptive document title, a single `h1`, and a postmortem `h2` are present.
- Buttons and generated choices are native `<button type="button">`; number-key shortcuts map to the same button activation, and R/Space behavior is documented visually.
- The table caption and column scopes are present; `aria-pressed` is correctly used for sound.
- `@media (prefers-reduced-motion: reduce)` covers animation, transitions, and smooth scrolling; JS also checks the media query.
- No horizontal overflow or mobile layout was verified here; run a 390px viewport test after target-size fixes.
